# 킥오프 체크리스트

외주 프로젝트에 필요한 자료·계정·정책 목록이다. **개발 범위로 정해진다.** `templates/library.json`에 51개 표준 항목이 있고, 항목마다 어떤 기능이 있을 때 필요한지(`when`), 언제 필요한지(`needBy`), 받는 데 며칠 걸리는지(`leadDays`), 고객사에 물을 입력 칸(`fields`)이 있다. `pm init --scope`와 `pm scope`가 범위에 맞는 항목만 넣는다.

## 범위 (`pm scope --list`)

| 묶음 | 기능 키 |
|---|---|
| 플랫폼 | `app`(모바일 앱), `web`(고객 웹), `admin`(관리자 웹) |
| 기능 | `payment`(결제·환불), `membership`(등급·포인트·쿠폰), `content`(공지·FAQ), `support`(1:1 문의), `commerce`(상품 판매), `location`(위치) |
| 로그인 | `social-kakao`, `social-naver`, `social-apple`, `social-google` |
| 발송 | `sms`, `alimtalk`, `email`, `push`, `marketing`(광고성 메시지) |
| 연동 | `vendor`(외부 공급사 API) |

범위를 바꾸면: 새로 필요한 항목은 추가되고, 범위에서 빠진 항목은 아직 아무 일도 없었을 때만(`missing`) '해당 없음'이 된다. 이미 요청했거나 받은 항목은 그대로 둔다. 앱에 소셜 로그인이 있으면 iOS 심사 때문에 Apple 로그인(`social-apple`)도 넣는다.

## 상태와 공

| status | 뜻 | 다음 행동 |
|---|---|---|
| `missing` | 아직 요청하거나 만들지 않았다 | 요청 시작일(`askBy`) 전에 요청하거나 준비한다 |
| `requested` | 고객사에 요청했고 답을 기다린다. 대기 일수(D+n)를 센다 | D+7이 넘으면 리마인드 |
| `received` | 답이나 자료를 받았고 검토가 남았다 | 검토해 확정하거나 고칠 점을 요청 |
| `confirmed` | 끝났다 | 없음 |
| `not_needed` | 이 프로젝트에는 필요 없다 | 없음 |

`ball`: `client`(고객사), `us`(우리), `dev`(개발팀). 고객사 답을 받으면 공은 우리에게 온다(검토).

`missing`은 "원본에서 확인해 보니 아직 없다"일 때만 쓴다. 기록을 못 찾았을 뿐이면 지금 아는 상태로 두고 `pm check <item> --guess --src "찾아본 곳"`으로 추정 표시를 한 뒤 사용자에게 묻는다. 콘솔·계정·통화로 처리된 일은 문서에 안 남는 경우가 많다.

## 필요 시점과 요청 시작일

| needBy | 날짜 |
|---|---|
| `kickoff` | 킥오프(없으면 개발 시작 2주 전) |
| `devStart` | 개발 시작 |
| `devMid` | 개발 기간 가운데(기능 개발) |
| `qaStart` / `qaEnd` | 고객사 QA 시작 / 최종 검수 |
| `storeSubmit` | 스토어 심사 제출(없으면 출시 2주 전) |
| `launch` | 출시 |

**요청 시작일(askBy) = 필요 시점 − 준비 기간.** 이 날이 지났는데 `missing`이면 '늦음'으로 표시되고 건강도가 '주의'로 오른다. 대시보드와 `pm kickoff`의 '이번 주 할 일'은 이 날짜 순서다.

준비 기간이 긴 것(먼저 요청할 것):

| 항목 | 준비 기간 | 메모 |
|---|---|---|
| PG 계약·운영 키 | 약 4주 | 라이브 심사 뒤 운영 키 |
| Apple Developer 법인 계정 | 3주 | D-U-N-S 번호 발급 포함 |
| 이용약관·개인정보처리방침 | 2주 | 우리가 초안, 고객사·법무 확인 |
| 카카오 알림톡 발신프로필 | 2주 | 비즈니스 채널 개설과 심사 |
| 외부 공급사 운영 키 | 2주 | 콜백 등록 담당을 정한다 |
| 문자 발신번호 | 10일 | 서류 인증 |
| Google Play Console | 10일 | 개발자 신원 확인 |

## 킥오프 4단계

`pm kickoff`. 계약 확인(계약서·범위 기준선·계약 점검) → 범위·SRS(SRS·일정·검수 기준·변경 절차) → 고객사 요청(요청 목록 전체를 보냄) → 기본 세팅(담당자·채널·보고·저장소·라벨). 단계는 순서대로 끝낼 필요는 없지만, 대시보드는 아직 안 끝난 첫 단계를 '지금 단계'로 보여 준다.

## 항목을 더하거나 고칠 때

라이브러리에 없는 항목은 `project.json`의 `checklist`에 직접 넣는다(형식은 `data-model.md`). `sheet: true`면 고객사 요청 목록에 나온다. 공개 연락처(고객센터, 개인정보 보호책임자)는 임시 값을 쓰지 않는다.
