# 계약 점검과 대금 단계

외주 계약서에서 PM이 놓치기 쉬운 것을 점검하는 목록이다. **법률 자문이 아니다.** 위험·없음 항목은 회사의 계약 담당자나 법무와 상의하도록 안내한다.

## 점검 12항목 (`pm contract`)

| id | 확인할 것 | 왜 | 보완 문구 예 |
|---|---|---|---|
| `scope-annex` | 범위 부속서(기능 목록)가 계약에 붙어 있다 | 범위 다툼의 1순위 근거 | "개발 범위는 별첨 기능 목록에 따르며, 목록에 없는 기능은 변경 요청으로 처리한다" |
| `acceptance` | 검수 방법·기간·통과 기준 | 검수가 끝나지 않으면 잔금이 밀린다 | "검수 요청 후 10영업일 안에 이의가 없으면 검수 완료로 본다" |
| `payment-terms` | 대금 단계와 조건이 검수와 연결 | 착수금·중도금·잔금의 지급 조건 | "잔금은 최종 검수 완료일로부터 14일 안에 지급" |
| `change-pricing` | 변경 요청 절차와 비용 산정 | 범위 밖 요청을 무상으로 떠안지 않게 | "변경 요청은 공수(인일 단가 × 일수)로 산정해 합의 후 진행" |
| `delay-liability` | 고객사 자료·결정 지연 시 일정 순연 | 공이 고객사에 있는 기간만큼 일정이 늦어지는 근거 | "갑의 자료 제공·의사결정이 지연되면 그 기간만큼 일정을 순연한다" |
| `deliverables` | 산출물·소스·계정 인도 범위와 시점 | 무엇을 언제 넘기는지 | "최종 검수 후 소스코드, 운영 문서, 관리자·스토어 계정(갑 명의)을 인도" |
| `ip` | 지식재산권 귀속과 예외 | 오픈소스·기존 모듈 | "을이 기존에 보유한 모듈과 오픈소스는 귀속 대상에서 제외하고 사용권을 준다" |
| `warranty` | 하자 보수 기간과 범위 | 무상 하자 vs 유상 유지보수 | "검수 완료 후 3개월간 개발 범위 내 결함을 무상 보수" |
| `maintenance` | 출시 후 유지보수 | 하자 보수 이후 지원 | "유지보수는 별도 계약으로 정한다" |
| `third-party-costs` | 제3자 비용 부담 | 서버·유료 API·스토어 계정 | "서버, 외부 서비스, 스토어 계정 비용은 갑이 부담하고 갑 명의로 계약" |
| `privacy-outsourcing` | 개인정보 처리 위탁·비밀유지 | 개발·운영 중 개인정보를 다루면 필요 | 개인정보 처리 위탁 계약(별도 또는 조항) |
| `termination` | 해지와 중도 정산 | 중단 시 진행분 정산 | "해지 시 진행된 단계까지의 대금을 정산한다" |

상태: `unchecked`(확인 전), `ok`(있음), `risk`(있지만 불리·모호), `missing`(없음), `na`(해당 없음).

```bash
pm contract check acceptance --status risk --note "검수 기간이 적혀 있지 않음"
```

계약서를 사용자가 주면 읽고 항목마다 상태와 한 줄 근거(조항 번호)를 `--note`로 남긴다. 계약서 원문은 워크스페이스에 복사하지 않고 위치만 체크리스트 `contract` 항목의 `res`에 남긴다.

## 이미 서명했다면

계약서를 고칠 수 없으면 위험 항목을 **킥오프 회의에서 합의로 보완**한다. 예: 고객사 지연 시 일정 순연 조항이 없으면, 킥오프에서 "회신 기한을 넘긴 만큼 해당 기능 일정이 밀린다"는 합의를 회의록과 요청 DB에 남긴다. `pm kickoff-kit --internal`의 '내부 준비'에 위험 항목이 모인다.

## 대금 단계

기본 제안: 착수금 30%(계약 체결), 중도금 40%(개발 완료·중간 검수), 잔금 30%(최종 검수 완료). 실제 계약에 맞게 `project.json`의 `contract.payments`를 고친다.

| 필드 | 설명 |
|---|---|
| `name`, `ratio`, `amount` | 이름, 비율(%), 금액(선택, 내부 정보) |
| `trigger` | 지급 조건(예: 최종 검수 완료) |
| `anchor` / `due` | 예정일을 정하는 일정(kickoff·devEnd·qaEnd…) 또는 직접 날짜 |
| `status` | `planned`·`invoiced`·`paid`, `paidAt` |

```bash
pm contract pay 중도금 --status invoiced
pm contract pay 중도금 --status paid --date 2026-12-28
```

계약 정보는 고객사 공유본에서 빠진다.
