# 고객사 요청서·리마인드

고객사에 나가는 글은 한 번에 답할 수 있게 쓴다. 고객사가 되묻게 만드는 글이 왕복을 늘리고 일정을 밀어낸다.

## 원칙

1. **무엇을, 왜, 어디로, 언제까지.** 요청 항목, 막히는 일정(필요한 이유), 전달 방법(받을 곳), 회신 기한을 꼭 넣는다.
2. **빈칸 대신 (제안) 값.** 아는 정보로 값을 채우고 "(제안)"으로 표시한다. 고객사는 "그대로 진행"이라고만 답해도 된다.
3. **결론만.** 이유를 길게 쓰지 않는다. 법 조항 설명, 구현 메모, 이슈 번호, 코드 용어, 진행 상태 열은 넣지 않는다. 개발자만 알면 되는 규칙은 개발팀 채널로 보낸다.
4. **고객사 말로.** 앱 푸시, 문자, 이메일, 카카오 알림톡처럼 고객사가 쓰는 말을 쓴다.
5. **한 번에 묶는다.** 같은 고객사에 보낼 요청이 여러 건이면 막는 일정이 빠른 순서로 한 글에 묶는다.
6. **보내는 것은 사람이다.** 초안만 만든다. 사용자가 보낸 뒤 `pm set <item> --status requested`로 요청일을 남긴다.

## 받을 곳과 진행 방식 고르기

| 상황 | 받을 곳 | 진행 방식 |
|---|---|---|
| 정책 문서(약관·처리방침·환불) | 고객 요청 DB | `draft`: 우리가 초안, 고객 확인 |
| 계정·키·권한(고객사만 만들 수 있음) | 고객 요청 DB | `ask` |
| 파일(로고, 계약서, 이미지) | 공유 드라이브 | `ask` |
| 정해야 할 것이 여럿이고 의견이 갈림 | 고객 요청 DB | `meeting`: 회의 안건으로 정하고 결과를 남김 |
| 우리가 정리하고 고객이 읽기만 하면 됨(SRS 등) | 저장소 문서 | `draft` |

## 요청서 형식

`pm request <item>`이 아래 형식으로 만든다. 사용자가 고친 뒤 보낸다.

```
[프로젝트] 취소·환불 정책 초안 확인 부탁드립니다

안녕하세요, 고객사 담당자님. 회사 PM입니다.
결제 개발 일정을 지키려면 아래 자료가 필요합니다.

■ 요청 항목: 취소·환불 정책
■ 필요한 내용: 취소 시점별 환불 기준과 예외
■ 회사가 (제안) 초안을 먼저 작성했습니다. 고칠 부분만 알려 주시면 됩니다.
■ (제안) 이용 24시간 전 전액, 이후 50%, 노쇼 환불 없음
■ 전달 방법: Notion 요청 DB (링크)
■ 회신 기한: 10/17(금)

(제안) 값으로 진행해도 괜찮은 부분은 ‘그대로 진행’이라고만 답해 주셔도 됩니다.
감사합니다.
```

`need`(필요한 내용)와 `proposal`((제안) 값)은 `project.json` 항목에서 온다. 비어 있으면 요청서도 비어 보이므로, 보내기 전에 채운다.

## 리마인드

- 요청한 지 7일이 넘으면 리마인드를 권한다. 막는 일정이 2주 안이면 더 빨리 보낸다.
- 리마인드에는 요청일, 막히는 일정, 회신 기한, 답이 없을 때 진행할 (제안) 값을 넣는다.
- 같은 항목을 세 번째 리마인드하게 되면, 글 대신 회의 안건이나 결정권자에게 올리는 것을 제안한다.

## 고객사 답을 받았을 때

- 원본(요청 DB 답, 메일)의 위치를 `res`에 남기고 상태를 바꾼다: `pm set <item> --status confirmed --res-label "..." --res-url "..."`
- 답 내용을 project.json이나 다른 문서로 길게 옮기지 않는다. 원본은 한 곳에 둔다.
- 개발팀에 전달할 때는 팀원이 물은 순서대로, 결론만 짧게 정리한다.
